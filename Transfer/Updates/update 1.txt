==========================================================================
 Daniel Skin Care - Fixing the 3 cloud issues (Series / Appointments / Album)
 Instruction sheet - Steps 0 to 3
==========================================================================

Background:
The three failing features (saving a series, booking an appointment, uploading
a photo to the album) were only ever tested in local localStorage mode, never
against real Firestore/Drive. In the cloud the write path is different, and
that is where the failures show up.

Most likely root cause: the Firestore security rules were never deployed to the
cloud project, so every write is silently rejected. Appointments also have an
independent bug (a "phone" field set to undefined), and the album adds an extra
layer of Google/Drive permissions.

Do the steps in order. After each step, check whether the problem is gone.


==========================================================================
 STEP 0 - Confirm the real error (2 minutes, changes nothing)
==========================================================================

Goal: see the actual error message so you know exactly what to fix.

1. Open the cloud site (your Netlify URL) in Chrome.
2. Press F12 (or right-click -> Inspect) to open the developer tools.
3. Go to the "Console" tab.
4. Try to save a series / book an appointment / upload a photo - same as before.
5. Look at the red error message and match it to this table:

   - "Missing or insufficient permissions"
        => Firestore rules problem. Go to STEP 1.

   - "Unsupported field value: undefined"
        => The phone bug in appointments. Go to STEP 3 (part A).

   - An error with 401 or 403 from googleapis.com
        => Drive token / permissions problem. Go to STEP 2.

   - "popup" / "unauthorized-domain" / "auth/popup-blocked"
        => Domain not authorized in Firebase Auth. Go to STEP 2.

Note: you will most likely see "Missing or insufficient permissions" - that
confirms Firestore rules are the main problem. Either way, do STEP 1.


==========================================================================
 STEP 1 - Deploy the Firestore rules (fixes Series + Appointments + half of Album)
==========================================================================

Two ways. The manual way (A) is simplest and needs no installs.

--- Option A (manual, recommended) ---

1. Go to: https://console.firebase.google.com
2. Sign in with the account: skincaredaniel@gmail.com
3. Select the project: daniel-skin-care
4. In the side menu: Build -> Firestore Database.
5. If there is no database yet, click "Create database", pick a location
   (e.g. eur3 / europe-west) and confirm (you can start in Production mode).
6. At the top, click the "Rules" tab.
7. Delete everything there and paste exactly this instead:

   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /users/{uid}/{document=**} {
         allow read, write: if request.auth != null && request.auth.uid == uid;
       }
     }
   }

   (This is exactly the content of the firestore.rules file already in the project.)

8. Click "Publish".
9. Go back to the site, refresh (F5), and try to save a series. It should work now.

--- Option B (command line, if the Firebase CLI is installed) ---

1. Open a terminal in the project folder (c:\Users\e198564\Desktop\Utilities\Daniel)
2. If there is no CLI:  npm install -g firebase-tools
3. Sign in:             firebase login
4. Deploy:              firebase deploy --only firestore:rules
5. Go back to the site, refresh, and try to save.


==========================================================================
 STEP 2 - Google permissions for the cloud (needed for the Album / Google Drive)
==========================================================================

Part A - Add the Netlify domain as an authorized domain:

1. Firebase Console -> the daniel-skin-care project.
2. Build -> Authentication -> "Settings" tab.
3. Scroll to "Authorized domains".
4. Click "Add domain" and add your cloud site URL, e.g.:
      your-app-name.netlify.app
   (just the domain name, no https:// and no trailing /)
5. Save.

Part B - Authorize the Google consent screen (OAuth):

1. Go to: https://console.cloud.google.com
2. Make sure the daniel-skin-care project is selected (top-left, next to the name).
3. Menu: APIs & Services -> OAuth consent screen.
4. If the Publishing status is "Testing":
      - Scroll to "Test users" -> "Add users"
      - Add: skincaredaniel@gmail.com
      - Save.
   (Alternatively click "Publish app" to leave testing mode, but for a single
    user, adding her as a test user is enough.)
5. Make sure the scope named:
      https://www.googleapis.com/auth/drive.file
   appears in the list of scopes. If not, add it under "Scopes".
6. Make sure the Google Drive API is enabled:
      APIs & Services -> Enabled APIs & services -> search "Google Drive API".
      If it is not enabled, click Enable.

Part C - Test:

1. Go back to the site, sign out and sign back in with Google (to get a fresh token).
2. When uploading a photo, a Google permission window may pop up - approve it.
3. If the browser blocks pop-ups, allow pop-ups for the site and try again.


==========================================================================
 STEP 3 - Code fixes (exactly where to go, what to remove, what to insert)
==========================================================================

--- Part A: the phone bug in appointments (most important) ---

File:     src/screens/appointments/AppointmentForm.jsx
Location: around line 182, inside the payload object in the save() function.

Find this line:

      phone: form.mode === "existing" ? undefined : form.phone,

Replace it with this line (undefined becomes null):

      phone: form.mode === "existing" ? null : form.phone,

Why: Firestore forbids saving a field with the value undefined and throws an
error. For an existing client this field was undefined, so booking always
failed in the cloud.


--- Part B: try/catch in the appointment form (so the button won't get stuck greyed out) ---

File:     src/screens/appointments/AppointmentForm.jsx
Location: inside the save() function, around lines 193-202.

Find this block:

      let apptId = id;
      if (isEdit) await repo.update(id, payload);
      else apptId = await repo.add({ ...payload, inviteSent: false });

      if (form.sendInvite)
        navigate(`/appointments/${apptId}/send`, {
          replace: true,
          state: { from: isEdit ? "calendar" : "appointments" },
        });
      else navigate("/calendar", { replace: true });

Replace it with this block:

      let apptId = id;
      try {
        if (isEdit) await repo.update(id, payload);
        else apptId = await repo.add({ ...payload, inviteSent: false });
      } catch (e) {
        setSaving(false);
        alert("Failed to save the appointment: " + (e?.message || e));
        return;
      }

      if (form.sendInvite)
        navigate(`/appointments/${apptId}/send`, {
          replace: true,
          state: { from: isEdit ? "calendar" : "appointments" },
        });
      else navigate("/calendar", { replace: true });

Why: if the save fails, the button goes back to active and a message is shown,
instead of the button staying greyed out with no feedback.


--- Part C: try/catch in the Series screen ---

File:     src/screens/Series.jsx
Location: the add() and saveEdit() functions, around lines 35-56.

1) Find the add() function:

      async function add() {
        if (!valid(draft)) return;
        await repo.add(payload(draft));
        setDraft(EMPTY);
        setAdding(false);
      }

   Replace it with:

      async function add() {
        if (!valid(draft)) return;
        try {
          await repo.add(payload(draft));
        } catch (e) {
          alert("Failed to save the series: " + (e?.message || e));
          return;
        }
        setDraft(EMPTY);
        setAdding(false);
      }

2) Find the saveEdit() function:

      async function saveEdit() {
        if (!valid(editDraft)) return;
        await repo.update(editId, payload(editDraft));
        setEditId(null);
        setEditDraft(null);
      }

   Replace it with:

      async function saveEdit() {
        if (!valid(editDraft)) return;
        try {
          await repo.update(editId, payload(editDraft));
        } catch (e) {
          alert("Failed to update the series: " + (e?.message || e));
          return;
        }
        setEditId(null);
        setEditDraft(null);
      }

Why: same as appointments - if the write fails, a message is shown instead of
"nothing happening".
