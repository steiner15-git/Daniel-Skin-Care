## 1. רקע ומטרות

התבקשו שיפורים למסך "ניהול עסק" בארבעה צירים:

1. **אמינות וחד-ערכיות** של המידע במסך ובכל הכנסה/הוצאה.
2. **חיבוריות** לפעולות שמתבצעות במסכים אחרים.
3. **פשטות** בניהול הכנסות והוצאות.
4. **הצגת מידע** שמאפשרת להבין איך לקדם את העסק.

### ממצאי הבדיקה בקוד שהובילו לדרישות

| ממצא | השלכה |
|---|---|
| "הכנסה" נרשמת במועד התקבול, גם כשהשירות ניתן אחר כך (סדרות, שוברים) | הכנסות לפי טיפול/סדרה מציגות תמונה מוטה |
| הרווח חושב בלי מע"מ | אי-התאמה לדיווח לרואה חשבון |
| הכנסה אוטומטית (מתור/סדרה/מוצר) ניתנת לעריכת סכום בלי עדכון המקור | אי-עקביות בין הכנסה לתור/חבילה/מלאי/יתרה |
| אין קישור מהכנסה חזרה למקור | קשה לעקוב אחרי הרשומה |
| הוצאה קבועה נמשכת ללא הגבלה | אי אפשר להגדיר "אחת לחודש למשך שנה" |

### היקף שנבחר (לפי החלטת המשתמשת)

לא כל ההצעות מומשו. נבחרו רק פריטים בעלי ערך גבוה ושינוי מהותי מועט. נדחו במפורש: הוספה מהירה עם כפתור צף, סימון מרובה, יעדים חודשיים, ניצולת יומן, שולי רווח, כלי תיקון להכנסות ישנות בלי `clientId`, והפרדת "ערך שירות" מ"כסף שהתקבל".

## 5. ארכיטקטורה

### 5.1 עיקרון מרכזי — ערכים נגזרים, לא שמורים

הרעיון: **שומרים את מה שנקלט, ומחשבים את מה שנגזר.** הכנסה/הוצאה שומרת רק את הסכום הכולל; הנטו, המע"מ והשיעור מחושבים בכל קריאה מהגדרות שנת המס של התאריך.

**למה לא לשמור נטו ומע"מ על הרשומה:** מעבר רטרואקטיבי לעוסק מורשה היה הופך את הערכים השמורים למיושנים, ודורש עדכון המוני של רשומות (כתיבה מסוכנת ובלתי הפיכה). עם חישוב בזמן קריאה, מעבר סטטוס חל מיד על כל השנה, והחזרת הסטטוס מחזירה הכול. בנוסף, יש מקור אמת אחד.

**מחיר העיקרון:** כל מקום שמציג או מסכם סכומים חייב לעבור דרך הפונקציות ב-`utils/vat.js`. קריאה ישירה ל-`vatRate`, `amountBeforeVat` או `vat` אסורה (ראו §10).

### 5.2 מבנה הנתונים

**מסמך הגדרות חדש `users/{uid}/settings/vat`:**

```
{
  years: [{
    id: "2026",
    from: "2026-01-01", to: "2026-12-31",
    status: "exempt" | "licensed",
    exemptRate: 0,        // "מע"מ % לעוסק פטור (חישוב)"
    rate: 18,             // "מע"מ %"
    ceiling: 0,           // תקרת מחזור לעוסק פטור (₪), 0 = לא הוגדרה
    confirmed: true,
    confirmedAt: <ms>
  }]
}
```

**שדות חדשים על ישויות קיימות:**

| ישות | שדה | משמעות |
|---|---|---|
| `income` | `vatRate` (number \| null) | שיעור שנערך ידנית. `null` = נגזר משנת המס |
| `expenses` | `vatRate` (number \| null) | כנ"ל |
| `expenses` | `amountBeforeVat`, `vat` | מנוקים ל-`null` בעת שמירה. רשומות ישנות שמורות כפי שהיו, ומטופלות כשיעור ידני |
| `expenses` | `recurringEnd` (date \| null) | תאריך החיוב האחרון של הוצאה קבועה |
| `auditLog` | פעולה `vat_year_edit` | עריכת הגדרות מע"מ |

**אין קולקציות חדשות, אין שינוי ב-`firestore.rules`, ואין מפתחות `localStorage` חדשים.**

### 5.3 כללי חישוב (`utils/vat.js`)

- **איתור שנת מס** (`taxYearFor`): התאריך בתוך שנה שהוגדרה → אותה שנה. אחרי השנה האחרונה → השנה האחרונה שהתחילה לפניו. לפני כל השנים → ברירת מחדל (פטור, 0%).
- **שיעור פעיל** (`effectiveRate`): בשנת מורשה `rate`, בשנת פטור `exemptRate`.
- **פיצול** (`splitGross`): `net = gross / (1 + rate/100)`, `vat = gross − net`, עיגול לשתי ספרות.
- **הוצאה ישנה** (`expenseVat`): `vat` מהרשומה, `net = total − vat`, שיעור נגזר `vat / net`.
- **הכנסה/עלות לסיכום** (`incomeRevenue`, `expenseCost`): מורשה → נטו; פטור → סכום כולל.
- **מע"מ לתשלום** (`incomeVatDue`, `expenseVatCredit`): רק מרשומות בשנת מורשה.
- **רווח לשנה** (`profitForYear`): משמש להצגת "לפני/אחרי" באישור שינוי הגדרות.
- **מחזור לשנה** (`turnoverForYear`): סכום ההכנסות בשנת מס לפי מזהה השנה.
- **תזכורת** (`vatYearNeedsConfirmation`): אין שנה שמכסה את היום, או שהשנה לא אושרה.
- **תקינות** (`validateYears`): אזהרות על תקופות חופפות, פערים וטווח הפוך.

### 5.4 חוק העריכה בטפסים

- הסכום הכולל ושיעור המע"מ הם שני השדות הניתנים לעריכה (`VatFields.jsx`). הנטו וסכום המע"מ מחושבים תמיד.
- **ברירת המחדל לשיעור נגזרת בזמן רינדור** (מצב `rateInput = null`), ולכן משתנה אוטומטית עם תאריך הרשומה ועם טעינת ההגדרות, בלי `useEffect` שמסנכרן.
- עריכה ידנית של שיעור: `rateInput` מחרוזת, נשמר `vatRate`. כפתור "איפוס" מחזיר ל-`null`.
- **הכנסה:** סכום+תאריך → מספר חשבונית → שדות מע"מ → אמצעי תשלום → לקוחה → פירוט.
- **הוצאה:** תאריך → תיאור → שם עסק → מספר חשבונית → סכום כולל → שדות מע"מ → קטגוריה → הוצאה קבועה (+ סיום) → תמונה.
- **הוצאה ישנה בעריכה:** נטענת כשיעור ידני (נגזר מהחשבונית), ובשמירה `amountBeforeVat` ו-`vat` מנוקים.

### 5.5 מסך הגדרות מע"מ (`VatSettings.jsx`)

- רשימת שנות מס (החדשה ראשונה), עם תגית "מאושרת / לא מאושרת".
- **הוספת שנה:** כפתור שמעתיק את ערכי השנה הקודמת; נשארת "לא מאושרת" עד אישור.
- **אישור ערך:** כפתור שמסמן `confirmed` בלי שינוי ערכים.
- **עריכה:** סטטוס, שני שיעורים, תקרה ותקופה. שמירה אחרי עריכה נחשבת אישור.
- **שינוי שמשנה את הרווח:** אישור עם הרווח לפני ואחרי.
- אין מחיקת שנה (הפחתת סיכון).
- כל שינוי נרשם בלוג עם לפני/אחרי.

### 5.6 ייצוא וגיבוי

- **דוח שנתי** (`exportXlsx.js`): עמודות: סוג, תאריך, פירוט, לקוחה/עסק, קטגוריה/אמצעי תשלום, מספר חשבונית, **כולל מע"מ, נטו, מע"מ, מע"מ %**, סטטוס. שורת מידע בראש (סטטוס ושיעור השנה), שורות סיכום הכנסות/הוצאות, ושורת רווח עם ציון הבסיס (נטו / סכומים כוללים).
- **גיבוי** (`backup.js`): גיליונות הכנסות והוצאות עם אותן עמודות מע"מ; גיליון חדש "מעמ" (שנת מס, תאריכים, סטטוס, שיעורים, אישור). קורא את `settings/vat` בעת הבנייה.
- **גיבוי חכם** (`backupWatermark.js`, `useAutoBackup.js`): `maxUpdatedAt` מקבל מסמכי הגדרות נוספים (`extraDocs`), וה-hook נרשם ל-`settings/vat`. בלי זה, שינוי בהגדרות לא היה מפעיל גיבוי (נגזרים לא משנים `updatedAt` של רשומות).

### 5.7 הוצאות קבועות (`utils/recurring.js`)

- `pendingDates` עוצר כשהחיוב הבא אחרי `recurringEnd` (או אחרי היום).
- "מספר חיובים" מומר לתאריך סיום בעת השמירה (`endDateForCount`): שדה אחד קובע, ואין צורך לספור רשומות שנוצרו. הספירה כוללת את החיוב הראשון (תאריך התבנית), כלומר "חודשי למשך שנה" = 12.
- `recurringEnded`: התבנית סיימה את כל חיוביה.
- רשומות שנוצרות אוטומטית מעתיקות מהתבנית `total`, `vatRate`, `amountBeforeVat`, `vat` (ערכים חסרים כ-`null`, כי Firestore לא מקבל `undefined`).

### 5.8 מרכז "דורש טיפול" וסינון

- הלוגיקה ב-`utils/reminders.js` (`incomeMissingInvoice`, `expensesMissingReceipt`) ובפונקציות הקיימות (`pendingClosureAppts`, `unverifiedIncome`), משותפת עם הדשבורד והבאדג'ים.
- **"חשבונית חסרה" ו"הוצאה בלי תמונה" נספרות לשנה הנוכחית בלבד** (אחרת ההיסטוריה הישנה מציפה). הכנסות ₪0 והוצאות שנוצרו אוטומטית מהוצאה קבועה לא נספרות.
- `Business.jsx` מחזיק מצב `incomeMissing`, `expenseReceipt` ו-`drill`. לחיצה ידנית על טאב מאפסת אותם. הטאבים מקבלים `key` שתלוי בהם, כדי להיטען מחדש עם הסינון הנכון.
- ברירת המחדל "כל השנים" בהכנסות חלה רק על סינון "חסר אישור תשלום" (הכנסה לא מאומתת עשויה להיות משנה קודמת).

### 5.9 מימוש סדרות (`utils/seriesRealization.js`)

**עיקרון:** בסיס התקבולים נשאר הרשמי. המימוש הוא שכבה ניהולית שאינה מחוברת לסך ההכנסות, ולכן אין "הכנסה כפולה".

- **שווי מפגש** = סכום ההכנסה של הרכישה (נטו בשנת מורשה) חלקי מספר המפגשים הכולל.
- **התחייבות פתוחה** (`openSeriesLiability`): שווי המפגשים שנותרו בחבילות פעילות שלא פגו. חבילות שפגו עם מפגשים שלא נוצלו מוצגות בנפרד ואינן נרשמות כהכנסה.
- **שווי שמומש** (`realizedSeriesValue`): תורים שנסגרו וחויבו מחבילה, לפי תאריך התור.
- **גשר:** תקבולי סדרות בתקופה (מההכנסות עצמן) פחות שווי שמומש = שינוי בהתחייבות הפתוחה.
- **בסיס מימוש** (`SummaryByProduct.jsx`): מוציא מהחישוב הכנסות מסדרות, ומוסיף רשומות סינתטיות לפי תורים שנוצלו, בתאריך התור, בטיפול של התור (מצב טיפולים) או בשם הסדרה (מצב סדרות). בבסיס זה כבוי המקטע הבהיר המוערך הקיים, כי הערך כבר כלול. מצב "מוצרים" אינו מושפע.
- **משך מימוש** (`seriesCompletionStats`): ימים מהרכישה ועד המפגש האחרון שחויב, לחבילות שנוצלו במלואן.

### 5.10 מבט על ו-drill-down

- `SummaryOverview.jsx`: השוואות (`sumPeriod` לתקופה נוכחית, קודמת ואשתקד), הכנסות לפי מקור, הוצאות לפי קטגוריה, ותובנות סדרות. נסתר במצב קליניקה, כמו שאר הסיכומים.
- `utils/period.js`: `periodRange`, `previousPeriod`, `lastYearPeriod`, `inRange` (טווחים כמחרוזות `YYYY-MM-DD`).
- **drill-down:** קומפוננטת הסיכום קוראת `onDrill({ tab, year, from, to, q?, source?, category? })`. `Business.jsx` פותח את הטאב עם `initial` מתאים (`IncomeTab`/`ExpenseTab`).
- נקודות כניסה: כפתורי "הכנסות/הוצאות התקופה" בסיכום הכללי, כפתור "הכנסות ‹" בשורות לפי מוצר (בבסיס תקבולים בלבד) ולפי לקוחה, ושורות מקור/קטגוריה במבט על.

## 9. מגבלות ידועות

- **לא הורץ build ולא נבדקה התנהגות** (ראו §7).
- **הכנסות ישנות** לא עוברות מיגרציה: מע"מ נגזר מהגדרות השנה. ללא שנה מוגדרת הכול מחושב כפטור 0%.
- **תקרת המחזור** סופרת את כל ההכנסות בשנת המס לפי הסכום הכולל, כולל רכישות שוברים במועד הרכישה.
- **הכנסה שחלקה קוזז מיתרה:** המע"מ מחושב על הסכום ששולם בפועל. חבילה ששולמה כולה מיתרה מקבלת שווי מפגש 0.
- **מימוש סדרות:** מפגשים שהופחתו ידנית דרך עריכת החבילה (בלי תור) אינם נכללים בשווי שמומש.
- **בסיס מימוש** אינו מציג כפתורי drill (הרשימות מוצגות לפי תקבולים).
- **Drill-down לפי שם** הוא חיפוש טקסטואלי, ולכן עשוי לכלול גם רשומות עם שם דומה (למשל שם טיפול שמופיע בתוך שם סדרה).
- **"הכנסה בלי חשבונית"** כוללת גם הכנסות מזומן שלא מצריכות חשבונית; סופרת לשנה הנוכחית בלבד.
- **ספירת חיובים בהוצאה קבועה:** המרה לתאריך נעשית בעת השמירה. עריכה חוזרת נטענת כ"עד תאריך". חישוב החודש הבא שומר על ההתנהגות הקיימת (JavaScript, למשל 31 בחודש).
- **שנות מס חופפות או עם פער:** אזהרה בלבד, לא חסימה.
- **תצוגות "לוח שנה" ו"רשימה" ביומן** עדיין טוענות תורים לשנה המוצגת בלבד (Phase 4 §9); רק תצוגת "ממתינים" טוענת את כל התורים.
- **שורת מימוש בכרטיסיית הלקוחה** (שווי שמומש, מפגש אחרון, קצב ממוצע) לא נמסרה: היא דורשת החלפת `ClientCard.jsx` כולו. ניתן להכין בנפרד.

## 11. בדיקות QA ידניות מומלצות

**מע"מ**
1. הגדרות ← "מע"מ ושנות מס": הגדרת שנה, אישור, עריכה. בדשבורד נעלמת תזכורת המע"מ אחרי האישור.
2. הכנסה חדשה: סכום כולל ← נטו ומע"מ מחושבים. עריכת שיעור ← חישוב מחדש. איפוס ← חזרה לשיעור השנה. שינוי תאריך לשנה אחרת ← שיעור ברירת המחדל משתנה.
3. הוצאה חדשה: אותו דבר. הוצאה ישנה בעריכה: מוצג השיעור שנגזר מהחשבונית, ובשמירה השדות הישנים מנוקים.
4. מעבר שנה לעוסק מורשה: הודעת אישור עם רווח לפני/אחרי; הסיכום מציג נטו וכרטיס "מע"מ לתשלום"; "לפי מוצר" ו"לפי לקוחה" תואמים לסך הכללי. החזרה לפטור מחזירה את המצב.
5. שנת פטור עם שיעור ידני בהוצאה (למשל 18%): הרווח נשאר מחושב מהסכום הכולל.
6. ייצוא Excel: ארבע עמודות מע"מ, שורת סטטוס בראש, סיכומים ורווח.
7. גיבוי: "גיבוי עכשיו" ← גיליון "מעמ" ועמודות מע"מ. אחרי שינוי בהגדרות בלבד, הגיבוי האוטומטי הבא לא מדלג.

**שיפורי מסך**
8. הוצאה קבועה חודשית עם 12 חיובים: תאריך החיוב האחרון בטופס; אחרי המועד אין רשומות נוספות; תגית "הסתיימה".
9. רשימות: שורת סיכום מתעדכנת עם הסינון; קיבוץ חודשי כשמיון לפי תאריך; סינון לפי מקור.
10. "דורש טיפול": ספירה נכונה, וכל פריט מוביל לרשימה המסוננת. לחיצה ידנית על טאב מאפסת את הסינון.
11. תגית מקור: הכנסה מתור/סדרה/מוצר/שובר פותחת את הלקוחה בטאב הנכון.
12. עריכת סכום בהכנסה אוטומטית: הודעה ואישור לפני שמירה.
13. חשבונית כפולה: אזהרה בהכנסה (מספר זהה) ובהוצאה (מספר ושם עסק זהים), ללא חסימה.
14. מד תקרה: תקרה בהגדרות שנת פטור ← פס התקדמות וצבעים לפי אחוז.

**סדרות, מבט על ו-drill-down**
15. כרטיס "סדרות פתוחות" מול חבילות פעילות בכרטיסיות הלקוחות.
16. גשר הסדרות: תקבולים פחות מימוש שווה לשינוי, ומתאים לתורים שחויבו מחבילה.
17. מתג בסיס מימוש: סך כל הזמן זהה בשני הבסיסים; חודש הרכישה אינו כולל את הסדרה בבסיס מימוש.
18. מבט על: ההשוואות תואמות לסיכום הכללי; אחוזי הקטגוריות מההכנסה נכונים.
19. Drill-down מכל נקודות הכניסה: התאריכים, החיפוש, המקור והקטגוריה מוגדרים כצפוי.

**תצוגת "ממתינים" (§13)**
20. ניהול עסק ← סיכום ← "דורש טיפול" ← תורים ממתינים: נפתח היומן בתצוגת "ממתינים", והמספר בטאב זהה למספר בבאדג' של אייקון היומן.
21. תור ממתין משנה קודמת מופיע בתצוגה (גם כשלוח השנה מציג את השנה הנוכחית).
22. הרשימה ממוינת מהישן לחדש ומקובצת לפי תאריך; בכל שורה "אישור ביצוע", עריכה, זימון וביטול.
23. אישור ביצוע (כולל חיוב מחבילה) וביטול תור מתצוגת "ממתינים" חוזרים לאותה תצוגה, והתור שטופל נעלם ממנה; כשהרשימה מתרוקנת מוצגת "אין תורים ממתינים לסגירה".
24. אישור ביצוע מלוח השנה או ממסך הבית חוזר למקום שממנו הגעת (ללא שינוי). "הצג הכל" בדשבורד פותח את תצוגת "ממתינים".

## 13. תיקון אחרי בדיקת הרצה: ניווט לתורים הממתינים לסגירה

### 13.1 התקלה

מ"ניהול עסק ← סיכום ← דורש טיפול" הקישור לתורים הממתינים לסגירה פתח את היומן בתצוגת **לוח שנה**. תצוגה זו מציגה רק את היום הנבחר (ברירת מחדל: היום), ולכן לא היה קל להבין איזה תור ממתין. הקישור "הצג הכל" בדשבורד סבל מאותה בעיה.

**בעיה נסתרת:** `Calendar.jsx` טוען תורים לשנה המוצגת בלבד (Phase 4 §9), בעוד הבאדג' על אייקון היומן ומרכז "דורש טיפול" סופרים את **כל** התורים. תור ממתין משנה קודמת נספר אך לא הוצג, והמספר לא התאים למה שנראה ביומן.

### 13.2 ההחלטה

נבחרה תצוגה שלישית ביומן ("ממתינים") במקום סינון בתוך תצוגת הרשימה. הסיבות: סינון ברשימה היה מתערבב עם "הצג עבר" וסינון הטיפול, והיה מוגבל לשנה המוצגת. כמו כן הוחלט שאישור ביצוע מהתצוגה הזו חוזר אליה.

### 13.3 דרישות

| מזהה | דרישה |
|---|---|
| **PN-1** | בבורר של היומן טאב שלישי "ממתינים (N)", לצד "לוח שנה" ו"רשימה". המספר מוצג רק כשהוא גדול מאפס |
| **PN-2** | התצוגה מציגה את כל התורים הממתינים לסגירה מכל השנים, הישן ביותר ראשון, מקובצים לפי תאריך |
| **PN-3** | הספירה והסינון לפי `pendingClosureAppts` (שמזינה גם את הבאדג' בבר התחתון, את "דורש טיפול" ואת הדשבורד), כך שהמספר זהה בכל המקומות |
| **PN-4** | בכל שורה אותן פעולות כמו בשאר התצוגות: אישור ביצוע, עריכה, זימון וביטול (אותו `ItemRow`) |
| **PN-5** | כניסה דרך `/calendar?view=pending` מהפריט "תורים ממתינים" ב"דורש טיפול" ומהקישור "הצג הכל" בדשבורד |
| **PN-6** | אישור ביצוע (כולל ניכוי מחבילה), ביטול תור וכפתור "חזרה" במסך אישור הביצוע חוזרים לתצוגת "ממתינים" כשהכניסה הייתה ממנה |
| **PN-7** | מצב ריק: "אין תורים ממתינים לסגירה" |

### 13.4 ארכיטקטורה

- **`Calendar.jsx`:** קורא את `?view=` ומאתחל את התצוגה (`pending` או ברירת מחדל `month`). טוען את כל התורים דרך `useCollectionData("appointments")` (מנוי משותף שכבר פעיל בבר התחתון, ללא עלות רשת נוספת), לצד הטעינה המוגבלת לשנה שמשרתת את לוח השנה והרשימה.
- **`PendingView`** (קומפוננטה חדשה בתוך `Calendar.jsx`): מקבצת לפי תאריך ומציגה `ItemRow` רגיל.
- **העברת המקור:** `closeFrom(from)` מנווט למסך אישור הביצוע עם `state: { from }`, כש-`from` הוא `"calendar"` (לוח שנה ורשימה) או `"pending"` (תצוגת ממתינים).
- **`CloseAppointment.jsx`:** נקודת החזרה נקבעת לפי `location.state.from`: `dashboard` ← `/`, `pending` ← `/calendar?view=pending`, אחרת `/calendar`. **לא השתנתה לוגיקת הסגירה, הניכוי, ההכנסה או הלוג.**
- **קישורים:** `Business.jsx` (פריט "תורים ממתינים" ב-`AttentionHub`) ו-`Dashboard.jsx` ("הצג הכל") מצביעים על `/calendar?view=pending`.

### 13.5 קבצים

| נתיב | שינוי |
|---|---|
| `src/screens/calendar/Calendar.jsx` | מוחלף: טאב שלישי, `PendingView`, קריאת `?view=`, `closeFrom` |
| `src/screens/appointments/CloseAppointment.jsx` | מוחלף: שורת `backTo` בלבד |
| `src/screens/business/Business.jsx` | מוחלף: קישור "תורים ממתינים" |
| `src/screens/Dashboard.jsx` | מוחלף: קישור "הצג הכל" |

### 13.6 מגבלות

- הרשימה מחושבת מהנתונים בעת טעינתם: תור שמועדו חלף בזמן שהמסך פתוח יופיע רק אחרי שהנתונים יתעדכנו.
- הפרמטר `view` נשאר ב-URL גם אחרי מעבר ידני בין הטאבים, ללא השפעה על התצוגה.
- אישור ביצוע שהתחיל מכרטיסיית לקוחה (`from: "clientCard"`) עדיין חוזר ללוח השנה, כפי שהיה.
